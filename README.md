# 碳迹 · 全民绿色生活碳积分与减排指南

> 第三届河南省高等学校信息技术应用创新大赛 · 赛题二参赛作品
>
> 一个运行在 **HarmonyOS（ArkTS + ArkUI，API 12）** 上的个人碳足迹记录应用：
> 记录低碳行为 → 按权威因子折算减排量 → 数据可视化 → 碳积分激励与城市碳普惠对接。

---

## 一、这个作品要解决什么

普通人每天的低碳行为（步行、骑车、节水节电、旧物回收、光盘行动）到底减了多少碳？
这些减排量又能换来什么？

「碳迹」把这条链路完整打通：

```
拍照/选图识别  →  活动量 × 碳排放因子  →  减排量（kg CO₂e）
                                              ↓
                          数据可视化看板（趋势 / 对比 / 占比 / 日历热力图）
                                              ↓
                          碳积分  →  虚拟徽章 · 电子证书 · 城市碳普惠真实权益
```

**内置的 14 条碳排放因子全部标注来源与基准情景**，不做模糊处理。

## 二、主要功能

| # | 功能 | 说明 |
|---|---|---|
| 1 | **低碳行为核算** | 四个类目 × 14 条因子；活动量 × 因子 = 减排量；每条因子标注基准与出处 |
| 2 | **数据可视化看板** | 折线趋势（含**上期对比幽灵线**）、分类柱状、占比环形、**12 周日历热力图**；日/周/月/年四种粒度 |
| 3 | **碳积分激励** | 每减排 1 kg CO₂e 得 100 积分；勋章墙、电子证书、积分流水 |
| 4 | **双碳科普专栏** | 8 篇图文，按政策 / 概念 / 数据 / 技巧分类 |
| 5 | **本地数据管理** | 一键备份（JSON）、导出报表（CSV）、清空数据；**数据全部保存在本机，不上传云端** |

### 四个创新点

| # | 创新点 | 说明 |
|---|---|---|
| 1 | **超级终端多设备同步** | 基于 HarmonyOS 分布式数据服务，双机登录同一账号即可同步；冲突以最新时间戳为准，同步面板完整展示流转过程 |
| 2 | **端侧 AI 图片识别** | MindSpore Lite 在本机推理（MobileNetV2），拍一张照片自动识别低碳行为并预填；**图片全程不出设备** |
| 3 | **城市碳普惠平台对接** | 完整实现「绑定 → 上报 → 查询 → 兑换」四环节，保留真实接口的异步、错误码、库存与幂等语义 |
| 4 | **智能服务与社交分享** | 每日三条个性化任务（短板优先）、生活建议、一键生成减排成绩单分享图 |

## 四、怎么跑起来

### 前置

- DevEco Studio（本项目在 **26.0.0** 上实测）
- HarmonyOS SDK（工程声明 `compatibleSdkVersion 5.0.0(12)`，满足赛题「API ≥ 12」要求）

> ⚠️ **工程路径不能含中文** —— hvigor 会硬性拒绝。
> 所以工作区里的 `project/` 是**源码正本**，构建时要同步到纯英文路径。

### 构建（不需要设备）

```bash
tools/preview.sh build          # 同步到 /tmp 构建 → 本地签名 → 产出可安装 HAP
```

它做三件事：把源码同步到 `/tmp/carbon-footprint`（纯英文路径）、调用 hvigor 构建、
再用 SDK 自带的调试签名材料做本地签名 —— **全程不需要登录华为账号**。

### 跑到模拟器上

```bash
tools/emulator.sh start && tools/emulator.sh wait   # 启动模拟器
tools/preview.sh all                                # 构建 → 安装 → 五页签逐页截图
```

### 回归测试

```bash
tools/test-logic.sh                 # 40 项纯逻辑断言（因子算术、任务推荐、生活建议、分享文案）
python3 tools/icon/check_icons.py   # 24 个图标自检（裁切 / 结构 / 页签视觉重量一致性）
```

## 五、设计说明

界面遵循《HarmonyOS 设计规范》的官方参数：

- **圆角五档** 4 / 8 / 16 / 20 / 32 vp，且**层级越高圆角越大**
- **间距**优先取 4 / 8 的倍数（卡片之间 12、卡片内边距 16、屏幕左右 16）
- **文本四级**：85% / 60% / 40% / 20% 黑，而不是所有文字一个颜色
- **卡片阴影**的 `radius`/`offset` 单位是 **px 不是 vp**，需 `vp2px` 换算
- **动效**用物理弹簧曲线而非线性曲线

设计令牌集中在 `entry/src/main/ets/common/Theme.ets`，
通用视觉组件集中在 `entry/src/main/ets/view/Common.ets`（9 个，零第三方依赖）。

> 视觉改造的完整诊断、市面同类项目调研与实施方案见
> [`前端美化-交接说明.md`](前端美化-交接说明.md) 与 [`.research/前端美化方案.md`](.research/前端美化方案.md)。

## 六、数据来源与严谨性

内置 14 条碳排放因子，每条都标注**基准情景 + 数据出处**：

| 类别 | 主要来源 |
|---|---|
| 用电 | 生态环境部、国家统计局《关于发布 2023 年电力二氧化碳排放因子的公告》（公告 2025 年第 47 号）表 3 河南省 `0.5897 kgCO₂/kWh` |
| 出行 | 中国产品全生命周期温室气体排放系数库（CPCD 2023） |
| 部分条目 | 中国官方尚未发布对应因子，采用英国 DEFRA 2025 口径，**并在应用内逐条标注** |

同一指标多来源存在差异（例如地铁 `8.81` vs `43.14 gCO₂e/人·km`，相差 4.9 倍），
应用内保留了口径说明而不是取一个数字了事。详细查证见
[`因子库数据来源与折算方法.md`](因子库数据来源与折算方法.md)。

## 七、已知限制

- **分布式同步**需要在真机上验证（模拟器不具备分布式软总线能力）
- **端侧 AI 识别**的标定表需要在真机上用真实照片标定（Core Vision Kit 官方不支持模拟器）
- **城市碳普惠平台**为本地模拟实现：真实平台未对个人开发者开放接口，
  但对齐了真实接口的异步、错误码、库存与幂等语义，将来替换通信层即可对接
