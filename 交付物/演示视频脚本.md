## 二、这一版改了什么（也是重做的原因）

上一版成片停在 v3.3；v3.4 改的是**信息架构**，画面必须跟着变：

1. **新增「记录」页（00:43–00:59）**。赛题把「支持分类查询历史记录」写在看板那一条下面，
   旧版却把筛选 + 全量列表垒在保存按钮底下。现在下沉成整屏二级页：五等分账页签、表头给合计、
   每行可删；入口只有两个——看板图例的任意一行、记一笔页尾的「全部〉」。演示里两个入口都要走到。
2. **记一笔页尾收口**。只留 3 条最近记录，条数并入表头。镜头不能再拍「一大串列表」。
3. **看板口径统一**。统计粒度从一张卡降成一行分段；日 / 周 / 月 / 年按日历切，三张图同源。
   演示时要**切一次粒度**，让评委看到三张图一起动，而不是只动折线。
4. **积分「徽章」与「证书」合一**。原来两张卡隔着一屏；现在卡内分「可兑换 / 已获得」，
   表头写「已获得 1/4」。演示要切到「已获得」，让证书票面露出来。
5. **科普十张卡收成一页 + 八行**。演示里点一行就地展开，不要逐张卡翻。

因此总时长从 1'52" 到 **2'16.6"**（按录好的人声实测、并剪掉首句后），多出来的时间一半是记录页那一段，
一半是这次读得比 TTS 慢（约 3.4 字/秒）。

## 三、数据基准与环境

**数据基准（与截图、设计文档一致）**：12 条记录、累计 21.75 kg CO₂e、累计 2,175 分、
已兑换植树证书（300 分）余额 1,875 分、连续 5 天 / 11 天有记录、徽章与证书已获得 1/4。

成片里的数字就是这一组；如果现场演示或要重录，按下面这条把数据摆回同样状态：

- **不要清库，只删一条重复记录**。记录页里有两笔一模一样的「步行 6 公里」（10-30）。
  录屏时「记一笔」先补一笔今天的 6 公里（+1.17 kg / 117 分，13 条 / 22.92 kg），
  随后在记录页把那条重复的旧记录删掉（−1.17 kg / 117 分）。
  一加一减，收尾正好回到 **12 条 / 21.75 kg / 2,175 分 / 余额 1,875 分**，与截图、PPT、设计文档一致。
  删除动作也正好落在 00:43–00:59 那一段，一石二鸟。
  清库不可取——「植树证书已拥有」「已获得 1/4」都会丢，旁白和画面对不上。
- 若必须重灌：先跑 `python3 tools/seed-demo-data.py --plan "travel:6:0,food:2:1,energy:4:2,recycle:2:0"`，
  再补一笔 6 公里步行、兑换植树证书，并把旁白里出现的数字按实际改。本稿只在「一点一七公斤」处
  硬编码了数字，其余都写成「条数和合计一起变」这类说法，重灌的风险因此可控。

## 四、已经做完的流水线

**1）旁白母带**：`交付物/旁白_碳迹_v3.4_母带.m4a`（2'21.6"，−16 LUFS，峰值 −1.2 dBTP）。
34 句的真实起止由 `align_narration.py` 按停顿切出来，落在 `参考资料/旁白对齐表.md`
与 `参考资料/旁白对齐.json`（`segments` 就是第一节那 10 段）。

**2）页面截图**：模拟器在线时逐页截，统一是 21.75 kg / 12 条 / 1,875 分这套数据：

```bash
python3 - <<'PY'
import sys; sys.path.insert(0, "tools/docs"); import ui
ui.tab("记一笔"); ui.m_to_top(); ui.shot("素材/截图/v3.4/10-记一笔-顶部.jpeg")
ui.tab("看板");   ui.m_to_top(); ui.shot("素材/截图/v3.4/20-看板-树与头部.jpeg")
PY
```

**3）合成**：`python3 tools/docs/make_demo_v34.py`——

- `SEGS` 定义 10 段的章节号、标题、2–3 条说明与 1–3 张截图；
- 段边界直接读 `旁白对齐.json`，右侧手机层按段内进度做 3.5% 推近；
- 字幕不依赖 ffmpeg 的 libass（本机没编），由 PIL 从同一份 JSON 逐句画在左下角，
  所以换一段旁白只需要重跑对齐 + 本脚本，字幕不会再漂。

产物：`交付物/演示视频_碳迹.mp4`（1920×1080、24fps、2'21.6"、约 18 MB）。

**若还想换回连续录屏**：`tools/docs/record_v34.py` 已能把模拟器窗口裁成 774×1309 录成分段片段
（`/tmp/rec34/sN.mp4`），替换 `SEGS` 里的截图即可，时间轴与字幕都不用动。
代价是「滚动停稳再点」和软键盘输入要人工盯两遍——这也是这一版先用截图的原因。

> `make_realdemo.py` 的 `SEG` 表仍是 v3.3 的 9 段与旧时长，且会预取 `seg1` / `s8` 的首末帧。
> 重录时把 10 段时长直接读 `参考资料/旁白对齐.json` 的 `segments`，片段名按
> `s1` 记一笔 / `s2` 记录 / `s3` 看板 / `s4` 看板下半 / `s5` 积分 / `s6` 科普 / `s7` 我的 / `s8` 年报，
> `int` / `out` 首尾各留 0.6 秒与 0.6 秒。
