# 任务 A · HarmonyOS Symbol 图标覆盖度核查

## A.0 结论先讲

在官方 **579 个** Symbol 里核对你点名的 **42 项语义**：

| 判定 | 数量 | 含义 |
|---|---|---|
| ✅ **有，语义贴合** | **22** | 可直接 `SymbolGlyph($r('sys.symbol.xxx'))` |
| ⚠️ **只能近似替代** | **7** | 语义偏移，用作图标会让人误解 |
| ❌ **完全没有** | **13** | 必须自绘（若把「CO₂」「火苗」两个子语义单列，则实为 **15** 项缺失） |

**一句话**：官方 Symbol 库是「鸿蒙自家 App 的用图需求」的产物，**碳中和、交通出行、餐饮、图表、奖章、地球这几大块是整体空白**。碳迹的品牌叙事（叶子 / 树 / CO₂ / 汽车 / 公交 / 自行车 / 图表 / 奖章）**全部要靠自绘 SVG 补齐**，覆盖率约 **52%**（22/42）。

> 版本判据：`support_version = HarmonyOS 5.0+` → API 12 可用；`5.1+` / `6.0` / `6.1` → **API 12 不可用**（此对应关系为**推断**，官方未逐条声明，请在 DevEco 试编译确认）。

## A.2 缺失语义的自绘替代配方（13 项一次画完）

**统一规格**（保证与官方 Symbol 视觉一致，这是"看起来不像拼凑"的关键）：`24×24` viewBox、`stroke-width: 2`、`stroke-linecap: round`、`stroke-linejoin: round`、`fill: none`，只画 `path/circle/line`，**不用 `<text>`、不用 `transform` 的 rotate/scale**（见 C.3 的 SVG 限制）。

| 缺失语义 | 自绘建议（一次画完，放同一个 `icons.ets` 常量表） |
|---|---|
| 碳足迹（叶子） | `M4 20 C4 10 12 4 20 4 C20 14 12 20 4 20 Z` + 一条叶脉 `M4 20 L14 10` |
| 树木 | 三角冠 `M12 3 L19 11 H5 Z` + 树干 `M12 11 V20` |
| CO₂ | 云轮廓 path + 下方小字用 **Path 拼**（不要用 `<text>`）或干脆只画云 + 两条上升小箭头 |
| 火苗 | 水滴形 path + 内层小水滴（双 path 叠出"焰心"） |
| 回收 | 三个 `arrowshape` 变体绕 120° 旋转——**注意 API 12 的 SVG `transform` 只支持 translate**，所以直接写三份坐标不同的 path，不要靠 rotate |
| 餐具 / 光盘 | 叉 `M7 3 V21` + 叉齿 3 短线；刀 `M17 3 C15 8 15 12 17 13 V21`；「光盘」画盘子圆环 + 一条干净弧线 |
| 汽车 | 车身圆角矩形 + 车顶梯形 + 两个 circle 轮 |
| 公交 | 竖长圆角矩形 + 车窗两条横线 + 两轮 |
| 自行车 | 两个 circle + 三角架 `M8 17 L12 10 L16 17` + 车把 |
| 奖章 | circle + 下方两条飘带 path |
| 礼物 | 方块 + 十字丝带 + 顶部蝴蝶结（两个小圆） |
| 图表 / 柱状图 | 三条不同高矩形 + 一条基线（**极简，反而更高级**） |
| 上升趋势 | 折线 `M3 17 L9 11 L13 15 L21 7` + 末端箭头 |

| 购物袋 | 圆角矩形 + 上方半圆提手 |

**改色**：`Image($r('app.media.ic_leaf')).fillColor($r('app.color.brand_green')).width(24).height(24)`
⚠️ **官方明确**：`fillColor` 会「**替换 SVG 图片中所有可绘制元素的填充颜色**」——**单色线性图标可以，双色/多色插画会被涂成一坨**。所以：**语义图标走单色 SVG + fillColor；插画走 PNG 或彩色 SVG 且不要调 fillColor**。

# 任务 B · 可用的开源 ArkUI 组件库（诚实评估）

## B.0 结论先讲：**不建议引入任何第三方 UI 组件库**

这是本次调研最明确的结论，有四条硬证据：

1. **生态极薄**。ohpm 中心仓全部 **4282 个包**中，`UI Components & Design` 类 **911 个**，但**平均 popularity 只有 51**（likes/下载量级），绝大多数是「一个人发过一版」的长尾。
2. **头部库直接踩版本线**。呼声最高的 `@ibestservices/ibest-ui`（179 likes、70+ 组件、MIT）——**我下载 .har 解包实测 `compatibleSdkVersion: 21`**，API 12 工程根本编不过。同时它 `byteCodeHar: true` + `obfuscated: true`，**源码不可读不可改**。这条足以否掉整个"引入通用 UI 库"的路线。
3. **能用的都是"单点组件"**。实测 `compatibleSdkVersion = 12` 的那几个（弹窗、日历、加载动画）都是单一功能，为 1 个弹窗引入 1 个依赖 + 1 个传递依赖，**收益 < 成本**。
4. **离线的正确姿势不是"离线安装"，而是"联网一次、把 .har vendor 进工程"**。这是唯一可行路径（见 B.2），但它要求你手工管理依赖树、手工验证每个传递依赖——**竞赛 5 周周期里，这个风险换不来多少视觉收益**。

**唯一例外**：图表。`@ohos/mpchart` 已在《图表方案选型调研.md》里单独做过实测评估（结论：首选，Apache-2.0，TPC 官方，API 12 是它的基线），**那是刚需，不是"美化"**，不在此列。

## B.2 如果非要引入：唯一可行的离线路径

`.har` 在 registry 上是**可直接下载的静态文件**，不需要 `ohpm install` 也能拿到：

```bash
# 1. 查元数据（拿到 tarball 直链与版本）
curl "https://ohpm.openharmony.cn/ohpm/@ohos/mpchart"        # → dist.tarball
# 2. 直接下 .har（联网一次即可）
curl -O "https://ohpm.openharmony.cn/ohpm/@ohos/mpchart/-/mpchart-3.0.30.har"
# 3. 放进工程，用本地文件依赖引用（之后彻底离线）
```

```json5
// entry/oh-package.json5
{ "dependencies": { "@ohos/mpchart": "file:./libs/mpchart-3.0.30.har" } }
```

⚠️ **三个坑**：① 传递依赖要**手工全部下载**（如 `harmony-dialog → @pura/spinkit`）；② `byteCodeHar` 包编译快但**源码不可读不可改**，竞赛期间出 bug 只能提 issue；③ 源码 HAR 用你工程的 SDK 编译，**版本高于 API 12 的包会直接报错**——这正是 `ibest-ui` 被淘汰的原因。

## C.2 许可证陷阱（这几条最容易在答辩时被问倒）

1. **unDraw 的三条禁令**：官网原文明确**禁止** ① 复刻/转售 unDraw 本身、② 用于机器学习训练/微调、③ **把素材打包再分发**。用在自己的 App / 演示视频里**完全合规且无需署名**；但**不要**把 unDraw 的 SVG 批量塞进"素材包"随作品提交。
2. **Remix Icon 已不是 Apache-2.0**。仓库 `license` 字段是 `NOASSERTION`，README 指向自有的 *Remix Icon License v1.0*（2026-01 更新）。免费商用、无需署名，但**别在文档里写"Apache-2.0"**。
3. **Spline 免费档的"Personal"字样 + 导出水印 + Android/iOS 导出收费**——虽然服务条款里对 *Spline Library 内容* 提到 Standard Commercial License，但**免费档的导出限制使它不能作为 App 内置资产的生产工具**。要用 3D，走 **3dicons（CC0）**或 Blender 自制。
4. **Shapefest 禁"作为库再分发"**——单个图形用于 App 没问题，打包成"3D 图标库"分发不行。
5. **Blender 的 GPL 不影响你的产出物**：GPL 约束的是 Blender 软件本身；你用 Blender 做的模型/渲染图，**版权归你**，可自由商用。（无官方文档可引，这是 FSF/GPL 的通行解释，标注为**通用法律常识，非本次查证**。）
6. **图标库混用的风险**：Lucide/Tabler/Heroicons 是「描边 2px」风格，Material Symbols/IconPark 是「填充」风格。**混用会在界面上立刻显廉价**——建议**只选一套**（推荐 Lucide，ISC、覆盖全、风格与鸿蒙 Symbol 接近），缺口用自绘补齐。

## C.3 ArkUI 的 SVG 能力边界（**这是本次最重要的技术发现之一**）

来源：官方《SVG标签说明》<https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-basic-svg>，以及《Image》<https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-basic-components-image>。

**✅ 支持（比我预期的多得多）**

| 类别 | 支持内容 |
|---|---|
| 基础形状 | `<rect>` `<circle>` `<ellipse>` `<line>` `<polyline>` `<polygon>` `<path>` |
| 通用属性 | `id` `fill` `fill-rule` `fill-opacity` `stroke` `stroke-dasharray` `stroke-dashoffset` `stroke-opacity` `stroke-width` `stroke-linecap` `stroke-linejoin` `stroke-miterlimit` `opacity` `clip-path` `clip-rule` **`transform`（API 12 仅支持 translate！）** |
| **滤镜** | ✅ `<filter>` `<feOffset>` `<feGaussianBlur>` `<feBlend>` `<feComposite>` `<feColorMatrix>` `<feFlood>` |
| **遮罩 / 裁剪 / 图案** | ✅ `<mask>`、`<clipPath>`、`<pattern>` |
| **渐变** | ✅ `<linearGradient>` `<radialGradient>` `<stop>` |
| 图片 | `<image>`（`href` 支持 jpg/jpeg/png/bmp/**webp**/heic/base64，**不支持嵌套 svg**） |
| 动画 | ✅ `<animate>` `<animateTransform>`（**仅单元素属性/形变动画，不支持嵌套**） |
| 分组 | `<svg>` `<g>` `<use>` `<defs>` |
| 颜色 | `#rgb` `#rrggbb` `rgb()` `rgba()` + 常用颜色关键字 |

**❌ 不支持 / 未在支持清单中（负面证据）**

| 特性 | 状态 |
|---|---|
| **`<text>` / `<tspan>` / `<textPath>`** | ❌ **官方 SVG 支持清单中完全没有**——**SVG 里不要写字**，文字一律用 ArkUI `Text` 组件叠上去 |
| **`<foreignObject>`** | ❌ 未出现 |
| **CSS `<style>` / `class`** | ❌ 未在通用属性中列出 → **只用行内属性，别用样式表** |
| **`<feTurbulence>`（程序化噪声）** | ❌ **不在滤镜清单里** → **无法用 SVG 生成颗粒噪声**（这条决定了 D 的噪声方案） |
| `transform: rotate/scale/skew/matrix` | ❌ API 12 仅支持 `translate`；**API 21+ 且 `Image.supportSvg2 = true` 才支持** |
| `<image>` 内嵌 svg | ❌ 明确不支持 |

**Image 组件的其它硬限制（已查证）**

- **`backgroundImage` 不支持 SVG**（官方原文：API 22 及之前版本"**不支持 svg 图片**，以及 gif 和 webp 等类型的动图"）。**只有 `Image` 组件能吃 SVG。**
- **SVG 图源下这些属性不生效**：`renderMode`、`interpolation`、`objectRepeat`、`imageMatrix`、`autoResize`（解码尺寸）。
- **Base64 加载 SVG：API 26.0.0 起才支持** → **API 12 不能把 SVG 写成 base64 data URI**（但 PNG 的 base64 可以）。
- **`fillColor` 仅对 SVG 生效**，且会**替换所有可绘制元素的填充色** → 只适合单色图标。PNG 改色要用 `colorFilter`。

**给团队的落地结论**：从 Lucide/Tabler 下载的 SVG **可以直接放进 `resources/base/media/` 用 `Image($r('app.media.xxx'))`**——因为它们是纯 `path` + `stroke`，完全落在支持清单内。**唯一要做的预处理**：确认 SVG 里**没有 `<style>` 块、没有 `<text>`、没有 `transform="rotate(...)"`**（Figma/Illustrator 导出时经常自动加），有就手工删掉或让设计同学重导。

# 任务 D · 不依赖图片素材的「零素材美化」手法

每条都标了判定：**✅ 已查证**（给了官方文档 URL）/ **⚠️ 未查证（推测）** / **❌ 不可行**（说明原因）。

### D.1 多层渐变叠加 + 噪声 / 颗粒

- **多层渐变叠加**：✅ **已查证**（`linearGradient` / `radialGradient` / `sweepGradient` 已在旧报告 §3.1 覆盖，此处不重复）。新增建议：卡片用 `linearGradient` 打底 + 在 `Stack` 上层再叠一个 `radialGradient` 半透明光斑（`center` 放在左上角、`radius` 放大），两层叠加即有"材质感"。
- **噪声 / 颗粒：ArkUI 没有官方 noise API。** ✅ **已查证（负面）**：官方「视效与模糊」分类全表共 14 项（不透明度 / 图形变换 / 图像效果 / 形状裁剪 / 颜色渐变 / 前景色设置 / 前景属性设置 / 外描边设置 / 视效设置 / 组件内容模糊 / 运动模糊 / 点击回弹效果 / 特效绘制合并 / 组件内容填充方式），**无任何噪声/颗粒项**；`<feTurbulence>` 也不在 SVG 滤镜清单里。
- **可行的噪声做法（两条）**：
  1. ✅ **已查证**：用 `backgroundImage` 平铺一张**自制**的 64×64 透明 PNG 噪声贴图 —— 官方 `backgroundImage(src, repeat?: ImageRepeat)` **支持 `ImageRepeat`**（文档示例有 `ImageRepeat.X`/`ImageRepeat.Y`/`NoRepeat`）+ `backgroundImageSize({width:64,height:64})` 控制平铺密度。⚠️ 注意 PNG 可以平铺，**SVG 不行**（`backgroundImage` 不支持 SVG）。噪声图用 Python/PIL 本地生成即可（`random.gauss` 写 RGBA），**不需要下载任何素材**。
  2. ✅ **已查证 API 存在**：`Canvas` 的 `createImageData(sw, sh)` / `putImageData(imageData, dx, dy)` 可遍历像素写随机灰度，一次性生成噪声层。（性能上不如贴图，推荐方案 1。）
- ❌ **不可行**：SVG `<feTurbulence>` 程序化噪声（不在官方滤镜支持清单）。

### D.2 渐变边框

- ✅ **已查证，且是官方原生能力**：`borderImage` 的 `source` 参数类型是 `string | Resource | **LinearGradient**`，官方描述原文是「**图片边框或者渐变色边框设置接口**」，**API 9 起支持**。文档：<https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-universal-attributes-border-image>
  ```typescript
  Column()
    .width(160).height(96).borderRadius(16)
    .backgroundColor('#F2FFFFFF')
    .borderImage({
      source: { angle: 135, colors: [['#34D399', 0], ['#0EA5E9', 1]] },
      slice: { top: 1, bottom: 1, left: 1, right: 1 },
      width: { top: 1.5, bottom: 1.5, left: 1.5, right: 1.5 },
      repeat: RepeatMode.Stretch
    })
  ```
  这是**"1.5vp 渐变描边"**这一高级感单点的官方做法——比 `border({color})` 高级一个量级，且零素材。
- ⚠️ **未查证**：`borderImage` 与 `borderRadius` 同时使用时的圆角裁切表现（文档未明确说明），**建议先做 30 秒真机验证**。

### D.3 卡片内发光 / 高光边

- ❌ **不可行：ArkUI 没有 inset（内阴影）**。✅ **已查证**：`ShadowOptions` 的全部字段是 `radius` / `type`(API 10+，`ShadowType.COLOR|BLUR`) / `color` / `offsetX` / `offsetY` / `fill`——**没有 `inset`/`spread`**。`textShadow` 更明确写了「不支持 `type`、`fill` 字段」。
- ❌ **不可行：UI Design Kit 的点光源高级视效在 API 12 用不了**。`hdsEffect`（组件点光源、按压光效）**起始版本 6.0.0(20)**，且依赖 `SystemCapability.UIDesign.HDSComponent.Core`。文档：<https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ui-design-hdseffect>
- ✅ **已查证的替代组合（"伪内发光/高光边"）**：
  1. **1vp 半透明白描边**：`border({ width: 1, color: '#33FFFFFF' })` —— 在深色/彩色卡上直接产生"玻璃高光边"。
  2. **外发光**：`shadow({ radius: 24, color: '#5934D399', offsetX: 0, offsetY: 6 })`（**彩色 + 大 radius + 小 offsetY** 就是辉光而非投影）。
  3. **提亮**：`lightUpEffect(0.1~0.3)` 或 `brightness(1.05~1.15)` —— ✅ **已查证**：`lightUpEffect` 与 `sphericalEffect`、`pixelStretchEffect` **均为 API 12+**（`sphericalEffect12+` / `lightUpEffect12+` / `pixelStretchEffect12+`）。文档：<https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-universal-attributes-image-effect>
  4. **顶部一道高光渐变**：`Stack` 里叠一个高 1vp 的 `Row`，用 `linearGradient` 从透明→白 30%→透明。

### D.4 半透明叠层 + backdropBlur 做玻璃卡片

旧报告 §3.3 已覆盖 `blur`/`backdropBlur`/`backgroundBlurStyle` 基础用法，**这里只补三条本次新查证的坑**（都很容易踩）：

1. ✅ **已查证**：`backgroundBlurStyle` / `backdropBlur` / `backgroundEffect` **三者在同一组件上只有最后设置的那个生效**（官方原文："同一组件上同时设置多个背景模糊接口时，**仅最后一个设置的接口生效**，之前的模糊效果会被覆盖"）。**别想叠加，要叠就叠在子组件上。**
2. ✅ **已查证**：`blendMode(mode, BlendApplyType.OFFSCREEN)` 会让 `backgroundEffect`、`blur`、`linearGradientBlur`、`brightness` **截取不到正确画面**（官方原文列出）。用离屏混合就不要再指望背景模糊。
3. ✅ **已查证**：官方明确「**backgroundBlurStyle、blur 和 backdropBlur 为实时模糊接口，会每帧进行实时渲染，性能负载较高。当模糊内容和模糊半径都不需要变化时，建议使用静态模糊接口 blur**」。玻璃卡片如果内容不动，**优先用 `blur` 而不是 `backdropBlur`**。
4. ✅ **已查证（新能力）**：`linearGradientBlur`（**API 12+**，「为组件添加内容线性渐变模糊效果」）——做"顶部清晰、向下渐隐"的英雄区比整块模糊高级得多。文档：<https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-universal-attributes-image-effect>

### D.5 Canvas 画装饰性图形（波浪 / 网格 / 点阵 / 弧形）

- ✅ **已查证**：Canvas 2D 全套可用（API 8+），本次核对到的具体能力包括：`arc` / `arcTo` / `ellipse` / `bezierCurveTo` / `quadraticCurveTo` / `roundRect` / `rect`、`createLinearGradient`（→ `CanvasGradient` → `addColorStop`）`createRadialGradient` `createConicGradient`（**API 10+**）、`globalCompositeOperation`（含 **`'lighter'`**，做辉光叠加）、`shadowColor` / `shadowBlur`、`putImageData` / `createImageData`、`measureText`。文档：<https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-canvasrenderingcontext2d> 与 <https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-components-canvas-common-method>
- **推荐 4 个零素材底纹**：① 正弦波浪（`bezierCurveTo`，用 `getAreaChange` 拿宽度自适应）；② 网格点阵（双重 `for` 循环画 1.5px 圆点，低透明度）；③ 同心弧线（`arc` 叠 3~4 层递减透明度）；④ 底部弧形遮罩（`quadraticCurveTo` 填充）。
- ⚠️ **性能注意（官方原文）**：「Canvas 组件的宽或高**超过 8000px 时使用 CPU 渲染**，会导致性能明显下降」；且绘制指令会入队，「Canvas 组件不可见的情况下，应尽量避免频繁调用绘制接口」。

### D.6 用 `Circle`/`Ellipse`/`Path` 叠出「能量球」「进度环」「光晕」

- ✅ 旧报告 §3.5 已覆盖 `Shape`/`Path` 基础，**这里补组合技巧**：**光晕 = 底层 `Circle` 填 `radialGradient`（中心亮、边缘全透明）+ 中层 `Circle` 填实色 + 顶层 `Circle` 用 `borderImage` 渐变描边**——三层叠出"能量球"，全程零素材。
- ✅ **已查证**：`radialGradient` 的 `center` / `radius` 可调，配合 `opacity` 递减即可做多层光晕。
- ⚠️ **未查证**：`Shape` 系组件上 `blendMode(BlendMode.PLUS)` 的叠加表现（`BlendMode` 枚举含 `PLUS`，但未在官方文档中找到 `Shape` + `PLUS` 的示例）→ 建议**先用多层低透明度 `radialGradient` 模拟**，这是确定可行的路径。

### D.7 文本渐变（重点：**API 12 做不到官方式文字渐变**）

- ❌ **不可行：`Text.shaderStyle` 是 API 20+**。✅ **已查证**：官方《Text》文档中该方法标为 **`shaderStyle20+`**，原文「可以显示为径向渐变 `RadialGradientStyle` 或线性渐变 `LinearGradientStyle` 或纯色 `ColorShaderStyle` 的效果」。**API 12 工程用了直接编不过。**- ✅ **已查证：唯一可行路径是 Canvas `fillText` + `CanvasGradient`**。官方《画布绘制通用属性》明确 `fillStyle` 的类型是 `string | number | **CanvasGradient** | CanvasPattern`，且「类型为 `CanvasGradient` 时，表示渐变对象，**使用 `createLinearGradient` 方法创建**」；《通用方法》中 `fillText(text, x, y, maxWidth?)` 自 API 8 起支持。
  ```typescript
  const g = ctx.createLinearGradient(0, 0, 200, 0)
  g.addColorStop(0, '#34D399'); g.addColorStop(1, '#0EA5E9')
  ctx.font = 'bold 40vp sans-serif'
  ctx.fillStyle = g
  ctx.fillText('12.4', 0, 40)     // 渐变数字
  ```
  ⚠️ 代价：**文字失去 `Text` 组件的排版/无障碍/自动换行能力**，只适合**固定短文本**（大数字、标题）。正文千万别这么写。
- ✅ **已查证（备选）**：`textShadow` 自 **API 10+**，「**从 API 11 开始支持以数组形式入参，实现多重文字阴影**」——用 2~3 层同色不同 radius 的 `textShadow` 做**霓虹发光标题**，API 12 完全可用，且保留 `Text` 全部能力。**这是"发光文字"性价比最高的做法。**
- ❌ **不可行**：`Text` 没有 `textGradient` 之类的属性（已通读《Text》属性表，无此项）。

### D.8 大数字排版技巧

- ✅ **已查证：`fontFeature` 是 API 12+**。官方《Text》标为 **`fontFeature12+`**，原文「设置文字特性效果，**比如数字等宽的特性**」，入参格式 `normal | <feature-tag-value>`，`<feature-tag-value>` 为 `<string> [<integer> | on | off]`，多个用逗号隔开；**官方给出的等宽数字示例是 `"ss01" on`**。
  ```typescript
  Text('12.4').fontFeature('"ss01" on')   // 官方文档写法
  ```
- ⚠️ **需实测**：OpenType 的**标准等宽数字标签是 `tnum`**，但**官方文档的 `fontFeature` 属性列表中没有列出 `tnum`**（列表以表格呈现，正文提取时丢失）。**请务必在真机上分别试 `"ss01" on` 与 `"tnum" on`，用秒表式跳动的数字看是否抖动**——不抖就是生效了。这是"数字动画不左右晃"的关键，值得花 10 分钟实测。
- ⚠️ **未查证（布局常规手段，未逐条取官方文档）**：单位对齐用 `Row({ alignItems: VerticalAlign.Bottom })`，数字 `fontSize(44)` + 单位 `fontSize(14)` + `fontColor` 降一级透明度，底部对齐。`Text` 之间的基线对齐（baseline）**未在本次查证范围内**。
- ✅ 排版层级（大数字 + 小标签 + 弱化单位）本身不需要任何素材，**是零素材条件下"设计感"来源的第一名**。

# 零素材条件下最划算的 10 个美化手段（排序）

排序依据 = **视觉收益 ÷ (实现成本 × 失败风险)**，且**全部不需要任何外部素材**。

| # | 手段 | 为什么排这个位置 | 判定 |
|---|---|---|---|
| **1** | **双色 `linearGradient` 打底 + 一层低透明度 `radialGradient` 光斑** | 5 分钟改完，全 App 卡片/头部立刻从"灰白"变成"有材质"。收益/成本比最高 | ✅ 已查证 |
| **2** | **`borderImage` + `LinearGradient` 做 1.5vp 渐变描边** | **官方原生支持渐变边框**（API 9+），是"高级感"最强的单点改动，别人很少知道这个 API | ✅ 已查证 |
| **3** | **彩色大半径外发光**：`shadow({radius:24, color:'#5934D399', offsetY:6})` + `lightUpEffect(0.15)` | 三行代码拿到"发光卡片"，`lightUpEffect` 是 **API 12+** 正好可用 | ✅ 已查证 |
| **4** | **玻璃卡**：`backgroundColor('#B3FFFFFF')` + `blur` + `border({width:1,color:'#33FFFFFF'})` | 半透明白描边是玻璃质感的灵魂；**静态内容用 `blur` 而非 `backdropBlur`**（官方性能建议） | ✅ 已查证 |
| **5** | **Canvas 手绘环形进度**：`arc` + `createConicGradient` + `lineCap='round'` + 端点小圆点 | 比官方 `Progress(Ring)` 好看一档，是碳迹首页的主角元素 | ✅ 已查证 |
| **6** | **Canvas `fillText` + `createLinearGradient` 做渐变大数字** | **API 12 唯一可行的文字渐变路径**（`shaderStyle` 要 API 20）。只用于固定短文本 | ✅ 已查证 |
| **7** | **`textShadow` 数组做霓虹发光标题** | API 11+ 支持数组多重阴影，保留 `Text` 全部排版能力。与第 6 条互补（一个用于数字，一个用于标题） | ✅ 已查证 |
| **8** | **Canvas/Path 装饰底纹**：正弦波浪、网格点阵、同心弧 | 零素材填满"空状态页"，是"这 App 做过设计"的最便宜证据 | ✅ 已查证 |
| **9** | **`radialGradient` + 三层 `Circle` 叠"能量球/光晕"** + `animateTo(curve: curves.springMotion())` 做呼吸缩放 | 动效 + 渐变叠加，视频里最抓眼球；弹簧曲线旧报告已覆盖 | ✅ 已查证（`PLUS` 混合除外） |
| **10** | **排版本身**：`fontFeature('"ss01" on')` 等宽数字 + 大数字/小标签/弱化单位的三级层级 | 成本几乎为零，却决定"专业 vs 学生作业"；**注意 `tnum` 需实测** | ✅ API 已查证 / ⚠️ 标签需实测 |

**第 11 位（锦上添花，需要自制一张 PNG）**：64×64 噪声贴图 + `backgroundImage(..., ImageRepeat.XY)` 叠 3%~5% 透明度——**这是把"渐变塑料感"变成"高级磨砂质感"的最后一步**。噪声图本地生成，不算引入外部素材。

**与之相对，明确不要做的三件事**：① 不要为"美化"引入任何第三方 UI 库（B 节四条硬证据）；② 不要指望 SVG 写文字或做噪声（`<text>` / `<feTurbulence>` 均不支持）；③ 不要在 API 12 上规划 `shaderStyle` 文字渐变或 `hdsEffect` 点光源（分别要 API 20 / API 20）。
